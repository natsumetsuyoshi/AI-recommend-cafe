# AI-recommend-cafe 要件定義書（MVP）

最終更新: 2026-07-26

## 1. コンセプト

「今の気分」を入力すると、AIが気分に合ったカフェを地図上で提案してくれるWebアプリ。
単なる店舗検索ではなく、**気分 → 体験の提案**を差別化ポイントとする。

## 2. 前提・技術方針

| 項目 | 決定 |
|---|---|
| プラットフォーム | Webアプリ（ブラウザ） |
| カフェデータ | Google Places API |
| 地図表示 | Google Maps JavaScript API |
| AIレコメンド | Claude API |
| 開発ゴール | まずMVP（動く最小プロダクト）で検証 |

## 3. 想定ユーザー・利用シーン

| ペルソナ | シーン | 気分の例 |
|---|---|---|
| 作業したい人 | 集中して仕事・勉強 | 「静かに集中したい」 |
| 気分転換したい人 | 一人でリフレッシュ | 「なんかモヤモヤする」 |
| デート/友人と | 誰かと過ごす | 「おしゃれな雰囲気で話したい」 |

## 4. スコープ

### MVPに入れる
- 地図表示＋現在地取得
- 周辺カフェの表示（Google Places から取得）
- 気分入力（自由文 or 気分タグ選択）→ AIがおすすめカフェを3件提案＋理由
- 店舗詳細（写真・営業時間・評価・場所）
- お気に入り保存（ブラウザの localStorage）

### MVPに入れない（将来）
- ユーザー登録／ログイン、口コミ投稿
- 複数店舗をつなぐ「プラン」提案 ← 将来の目玉。MVPは「1店舗レコメンド＋理由」まで
- ルート案内、履歴パーソナライズ、ソーシャル共有

## 5. コア体験フロー

```
気分を入力（自由文 or タグ選択）
  ↓
現在地・時間帯を取得
  ↓
周辺カフェを Google Places で取得
  ↓
AI（Claude）が「気分 × 店舗情報」でマッチング＆理由生成
  ↓
おすすめカフェ 3件を地図＆カードで表示（理由つき）
```

## 6. AIレコメンド仕様

| 項目 | 内容 |
|---|---|
| 入力 | 気分（自由文）、現在地、時間帯 |
| 店舗データ | 名前・評価・レビュー抜粋・価格帯・営業状況・カテゴリ（Places由来） |
| 出力 | おすすめ3件＋各店の「なぜあなたの気分に合うか」1〜2文 |

- Google Places には「静か／作業向き」等の雰囲気タグが無いため、**MVPではレビューのテキストと評価をClaudeに読ませて雰囲気を推測**させる。
- 使用モデルはコストと品質のバランスで選択（後述のコスト試算参照）。

## 7. 画面（最小3枚）

1. **ホーム／地図画面** — 地図＋現在地＋気分入力欄
2. **レコメンド結果** — おすすめカードのリスト（理由つき）＋地図上にピン
3. **店舗詳細** — 写真・営業時間・評価・お気に入りボタン

## 8. 技術構成（たたき台）

- フロント: React ＋ Google Maps JavaScript API
- 店舗データ: Google Places API（Nearby Search / Place Details）
- AI: Claude API（気分×店舗のマッチング＋理由生成）
- **APIキーはバックエンド経由で扱う**（キー漏洩・課金保護のため軽いサーバーを1枚挟む）
- お気に入り: localStorage

## 9. 注意点（MVPでも押さえる）

- Google Places / Maps は従量課金 → 呼び出し回数の制御（キャッシュ、頻度制限）を最初から意識
- Google Places の利用規約 → データの保存・キャッシュ期間に制限あり
- Claude に渡すレビュー件数を絞ってトークンコストを抑える

## 10. コスト試算

> 価格は 2026年時点の公開レート（USD）。Google は SKU ごとに月間無料枠あり、
> Claude は完全従量課金（無料枠なし）。為替は概算で 1 USD ≒ 155 円とする。

### 単価（2026年 / 10K〜100Kボリューム帯）

| サービス | SKU | 単価 |
|---|---|---|
| Google Maps JS API | Dynamic Maps（地図表示） | $7 / 1,000 ロード（月10,000ロード無料） |
| Google Places API | Nearby Search | 約 $6.40 / 1,000 リクエスト |
| Google Places API | Place Details（Basic） | 約 $17 / 1,000 リクエスト（要求フィールドで変動） |
| Claude API | Opus 4.8 | 入力 $5 / 出力 $25（per 1M tokens） |
| Claude API | Sonnet 5 | 入力 $3 / 出力 $15（per 1M tokens） |
| Claude API | Haiku 4.5 | 入力 $1 / 出力 $5（per 1M tokens） |

### 1回のレコメンド体験あたりのコスト（概算）

想定: 地図1ロード＋Nearby Search 1回＋Place Details 3件＋Claude 1回
（Claudeは 入力≒3,000トークン / 出力≒800トークンで試算）

| 項目 | 計算 | コスト(USD) |
|---|---|---|
| 地図ロード ×1 | $7 / 1000 | $0.007 |
| Nearby Search ×1 | $6.40 / 1000 | $0.0064 |
| Place Details ×3 | $17 / 1000 × 3 | $0.051 |
| Claude（Opus 4.8） | 3000×$5/1M + 800×$25/1M | $0.035 |
| **合計（Opus）** | | **≒ $0.10 / 回（約15円）** |
| （参考）Claudeを Sonnet 5 に | 3000×$3/1M + 800×$15/1M | $0.021 |
| **合計（Sonnet）** | | **≒ $0.085 / 回（約13円）** |
| （参考）Claudeを Haiku 4.5 に | 3000×$1/1M + 800×$5/1M | $0.007 |
| **合計（Haiku）** | | **≒ $0.071 / 回（約11円）** |

> Places の Place Details が最もコストに効く。表示件数や要求フィールドを絞るのが節約の要。

### 月間コストのイメージ（Opus 4.8 / Google無料枠差引後）

| 月間レコメンド回数 | 地図ロード | Places系 | Claude | 月額合計(USD) | 月額(円) |
|---|---|---|---|---|---|
| 1,000回（個人検証） | 無料枠内 | 約 $57 | 約 $35 | **≒ $92** | 約 14,000円 |
| 5,000回（小規模公開） | 約 $0 | 約 $286 | 約 $175 | **≒ $461** | 約 71,000円 |
| 20,000回（成長期） | 約 $70 | 約 $1,148 | 約 $700 | **≒ $1,918** | 約 30万円 |

> 上記は Google Maps/Places・Claude の従量課金分のみ。デプロイ先は Vercel に決定しており、ホスティング費用は別途 Hobbyプラン無料 / Proプラン $20/席/月〜 がかかる。

### コスト削減の打ち手（MVPから意識）
1. **Places の呼び出しキャッシュ** — 同じエリアの検索結果を一定時間キャッシュ（規約の範囲内）
2. **Place Details のフィールドを最小化** — Basic フィールドのみ要求、詳細は必要時のみ
3. **Claude のモデル選択** — MVP検証は Sonnet 5 か Haiku 4.5 で十分。品質を見て Opus に上げる
4. **Claude のレビュー入力を絞る** — 上位数件のレビュー抜粋だけ渡す
5. **プロンプトキャッシュ** — 固定の指示部分をキャッシュして入力トークンを削減
